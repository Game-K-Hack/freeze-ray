## 它解决什么问题

Windows 可以用 `Ctrl + Win + ←/→` 切换虚拟桌面，但你正在看的一切会随着离开的桌面
一起消失。Freeze Ray 会把窗口钉住，让它**在每个桌面上都停留在完全相同的位置**。

这是一款秉承 **DeskPin** 精神的通知区域小工具，提供两个互不相干的操作：

- **保持在屏幕上** —— 窗口跟随你穿过所有虚拟桌面。
- **始终置顶** —— 窗口停留在其他窗口之上，也就是 DeskPin 的经典行为。

两者可以同时作用于同一个窗口。

## 运行要求

- **Windows 10**（在版本 19045、22H2 上构建并验证）。
- **.NET Framework 4** —— Windows 自带，无需安装任何东西。

> 在 Windows 11 上，用于虚拟桌面的未公开外壳接口具有不同的标识符。参见
> [已知限制](#已知限制)。

## 快速上手

1. 从[最新发布](https://github.com/Game-K-Hack/freeze-ray/releases/latest)下载
   `Freeze Ray.exe`，或者[自行构建](#从源码构建)。
2. 运行它。不会打开任何窗口，只在通知区域出现一个图标。
3. 点击图标 → **保持在屏幕上（所有桌面）…**
4. 光标变成应用的图标：点击你想保留的窗口。它的标题栏上会出现一个小标志。
5. 用 `Ctrl + Win + ←/→` 切换桌面：窗口依然在那里。
6. 想解除时，点击其标题栏上的标志即可。

可执行文件是自包含的：既不需要安装程序，也不需要 `assets` 文件夹。

## 使用方法

**不注册任何全局快捷键**，因此不会与其他程序冲突。所有操作都通过图标进行，
**左键或右键点击都会打开菜单**：

| 菜单项 | 作用 |
|---|---|
| **保持在屏幕上（所有桌面）…** | 进入拾取模式；随后点击的窗口将跟随所有桌面 |
| **始终置顶…** | 进入拾取模式；随后点击的窗口变为 `TOPMOST` |
| **已锁定的窗口 (n)** | 连同状态一并列出；点击其中一项即可解除 |
| **全部解除** | 让所有窗口恢复常态 |
| **设置…** | 打开设置窗口 |
| **退出** | |

### 拾取模式

点击前两项之一后，**光标会变成应用图标**，表示正在等待你指定窗口；下一次点击即完成
选择。这次点击被 Freeze Ray 吞掉，因此不会按到指针下方的任何东西。

- **Esc** 或**右键点击**取消。点击桌面或任务栏同样放弃，且不提示。
- 指定一个已锁定的窗口会解除它 —— 该操作是开关式的。
- 图标的悬停提示始终显示当前状态。

### 标题栏上的标志

被锁定的窗口会在**标题栏上得到该图标**，位于系统按钮左侧。**点击它即可解除窗口**
并移除标志。

窗口移动或调整大小时标志会跟随，最小化时消失，并在层叠顺序中紧贴窗口前方 ——
因此遮住目标窗口的其他窗口也会遮住标志。保持在所有桌面上的窗口会把标志一并带走。

使用自绘边框的窗口（浏览器、UWP 应用等）并不总会公开其标题栏的几何信息；此时标志
会放在可见边框的右上角。

## 设置

通过菜单中的**设置…**打开。窗口先显示图标、名称和**版本号**，然后是：

| 设置项 | 说明 |
|---|---|
| **开机启动** | 写入 `HKCU\...\CurrentVersion\Run`。注册表是唯一的事实来源：复选框会读回真实状态，写入失败时自动复位 |
| **退出时全部解除** | 避免留下被锁住的窗口 |
| **显示通知** | 只隐藏信息类气泡 —— **错误始终会提示**，因为让错误沉默会使一次失败的操作看起来像什么都没发生 |
| **语言** | 立即生效，包括菜单、悬停提示和通知 |
| **启动时检查更新** | 启动时向 GitHub 查询；除非有更新版本，否则不作提示 |

设置保存在 `%APPDATA%\Freeze Ray\settings.ini`，是一个可以手工阅读和修改的
`键=值` 文件。首次运行时语言跟随 Windows，否则回退为英语。共提供九种语言：英语、法语、德语、西班牙语、意大利语、日语、韩语、俄语和中文。

文案放在 [Strings.cs](../Strings.cs) 中，按语言各一张表，而不是资源文件，这样项目
仍可仅用 Windows 自带的编译器构建。新增一种语言，只需增加一张表和下拉列表中的一项。

### 更新

**检查更新**会针对所配置的仓库查询 GitHub 的公开发布 API，比较版本号，并询问是否
打开下载页面。

**本应用刻意不自我更新。** 替换正在运行的可执行文件需要一个辅助进程，而在没有签名
和完整性校验的情况下这样做会成为攻击途径 —— 对这种体量的小工具而言并不划算。

## 从源码构建

无需安装 SDK：Windows 中已有的 .NET Framework 4 自带 C# 编译器就够了。

```bat
build.bat
```

这会在源码旁生成 `Freeze Ray.exe`。图标**已嵌入可执行文件**，因此二进制文件可以
独立运行。

## 更换图标

| 文件 | 用途 |
|---|---|
| `assets/icon.png` | 源图标（512×512，透明）—— 通知区域图标、拾取光标和标题栏标志 |
| `assets/app.ico` | 多尺寸图标（16 → 256）—— 文件图标与窗口图标 |
| `assets/Freeze Ray.png` | 仅用于设置窗口顶部的插图 |

要更换图标，请替换 `assets/icon.png`，用任意图标编辑器制作包含九种常用尺寸（16、20、
24、32、40、48、64、128、256）的 `assets/app.ico`，然后运行 `build.bat`。

仅有一张 256×256 的图像是不够的：Windows 将不得不自行缩小它以适应通知区域（16×16）
和标题栏，结果模糊。

## 工作原理

### 虚拟桌面

把窗口保持在所有桌面上，用的正是任务视图右键菜单中*“在所有桌面上显示此窗口”*背后
的机制，由未公开的外壳 COM 接口 `IApplicationViewCollection` 与
`IVirtualDesktopPinnedApps` 提供 —— 参见 [VirtualDesktop.cs](../VirtualDesktop.cs)。

### 用覆盖层拾取，而非鼠标捕获

拾取依靠的是**覆盖所有显示器的透明图层**，而不是 `SetCapture`。鼠标捕获只在按住
按键期间、或指针位于捕获窗口之上时才会转发消息 —— 这正是 Spy++ 的查找工具需要
*拖动*使用的原因。在没有按下按键时，每个被划过的窗口仍会设置自己的光标，图标便
始终不会出现。有了覆盖层，指针始终位于我们自己的窗口之上：由它设定光标并接收点击。
参见 [WindowPicker.cs](../WindowPicker.cs)。

### 标志

标志是一个逐像素透明的窗口（`WS_EX_LAYERED` + `UpdateLayeredWindow`），因此图标的
抗锯齿在任何背景上都得以保留。它从不获取焦点，点击它不会让目标窗口失活，而其透明
区域会把点击放行到下方的标题栏。

**要移动标志**，只需 [WindowMarker.cs](../WindowMarker.cs) 中的一个设置：
`BUTTON_GAP`，即与第一个系统按钮之间的间距（4 px）。数值越小标志越靠右；小于零则
会压到“最小化”按钮上。

按钮区块的宽度无法直接读取：系统度量 `SM_CXSIZE` 报告 36 px，而 Windows 10 实际绘制
的按钮宽 46 px（逐像素测量：字形每 46 px 居中一次）。不过它能正确跟随显示缩放，
因此代码中采用 46/36 的比例。

### 否决“置顶”的应用

某些应用**拒绝**别人改动它们的层叠顺序：它们拦截 `WM_WINDOWPOSCHANGING`，顺手把改动
抵消掉。于是 `SetWindowPos` 会**返回成功却什么也没做** —— VLC 在播放视频时正是如此
（实测：调用整整一秒之后标志位依然缺失）。

因此代码中有两道防备：

- `SWP_NOSENDCHANGING` 标志会抑制该通知，剥夺应用的否决权；
- 调用之后**重新读取状态**，而不是相信返回值，好让真正的失败被报告出来，而不是被
  悄悄咽下。

### 通知

信息类气泡显示的是**应用图标**，而不是系统的蓝色“i”。WinForms 做不到这一点：
`NotifyIcon.ShowBalloonTip` 只接受系统图标，并拒绝其枚举范围之外的任何取值。于是
代码直接与外壳打交道（`Shell_NotifyIcon` 搭配 `NIIF_USER`），复用 WinForms 已创建
条目的内部标识 —— 参见 [Notifications.cs](../Notifications.cs)。万一这个内部细节
发生变化，代码会退回到标准气泡。

通知的标题栏显示 `Freeze Ray.exe`：Windows 在那里放的是可执行文件名。声明
`AppUserModelID` 并不能改变它（已验证）；只有在开始菜单安装快捷方式才可能显示不带
扩展名的名称。

## 已知限制

- 属于**提升权限**进程的窗口，只有在 Freeze Ray 同样以管理员身份运行时才能修改。
- 用于虚拟桌面的 COM 接口未公开，其标识符随 Windows 版本变化。这里采用的 GUID 属于
  **Windows 10 1803 → 22H2**，并在版本 **19045** 上验证。在 Windows 11 上，
  `IVirtualDesktopPinnedApps` 的 IID 不同，需要调整
  [VirtualDesktop.cs](../VirtualDesktop.cs)。
- 固定作用于窗口而非应用程序：窗口关闭后重新打开，需要重新固定。
