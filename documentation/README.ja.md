## 何ができるか

Windows では `Ctrl + Win + ←/→` で仮想デスクトップを切り替えられますが、見ていた
ものは離れたデスクトップと一緒に消えてしまいます。Freeze Ray はウィンドウを固定
し、**すべてのデスクトップでまったく同じ位置に表示し続けます**。

**DeskPin** の流れをくむ通知領域ユーティリティで、独立した 2 つの動作があります。

- **画面に保持** — ウィンドウがすべての仮想デスクトップに付いてきます。
- **最前面に固定** — ウィンドウが他より前面に留まります。DeskPin 本来の動作です。

同じウィンドウに両方を適用できます。

## 必要環境

- **Windows 10**（ビルド 19045 / 22H2 でビルドおよび検証）。
- **.NET Framework 4** — Windows に同梱済みで、追加インストールは不要です。

> Windows 11 では、仮想デスクトップに使う非公開のシェルインターフェイスの識別子が
> 異なります。[既知の制限](#既知の制限)を参照してください。

## はじめかた

1. [最新リリース](https://github.com/Game-K-Hack/freeze-ray/releases/latest)から
   `Freeze Ray.exe` をダウンロードするか、[自分でビルド](#ソースからビルドする)します。
2. 実行します。ウィンドウは開かず、通知領域にアイコンが現れるだけです。
3. アイコンをクリック →**画面に保持（すべてのデスクトップ）…**
4. カーソルがアプリのロゴに変わります。保持したいウィンドウをクリックしてください。
   そのタイトルバーに小さなロゴが付きます。
5. `Ctrl + Win + ←/→` でデスクトップを切り替えます。ウィンドウはそのままです。
6. 解除するには、タイトルバーのロゴをクリックします。

実行ファイルは単体で動作します。インストーラーも `assets` フォルダーも不要です。

## 使い方

**グローバルなキーボードショートカットは一切登録しません**。他のアプリと衝突する
おそれがありません。操作はすべてアイコン経由で、**左右どちらのクリックでもメニュー
が開きます**。

| 項目 | 動作 |
|---|---|
| **画面に保持（すべてのデスクトップ）…** | 選択モードに入り、クリックしたウィンドウが以後すべてのデスクトップに付いてきます |
| **最前面に固定…** | 選択モードに入り、クリックしたウィンドウが `TOPMOST` になります |
| **固定中のウィンドウ (n)** | 状態とともに一覧表示。クリックすると解除します |
| **すべて解除** | すべてのウィンドウを元に戻します |
| **設定…** | 設定ウィンドウを開きます |
| **終了** | |

### 選択モード

上の 2 項目のいずれかをクリックすると、**カーソルがアプリのロゴに変わり**、ウィン
ドウの指定を待っていることを示します。次のクリックで対象が決まります。そのクリック
は Freeze Ray が受け取るため、ポインターの下にあるものは操作されません。

- **Esc** または**右クリック**で中止します。デスクトップやタスクバーをクリックした
  場合もメッセージなしで中止します。
- すでに固定中のウィンドウを指定すると解除されます。動作はトグルです。
- アイコンのツールチップに現在の状態が常に表示されます。

### タイトルバーの目印

固定されたウィンドウには、システムボタンのすぐ左に**ロゴが表示されます**。
**そのロゴをクリックするとウィンドウが解除され**、目印も消えます。

目印は移動やサイズ変更に追随し、最小化すると消え、重なり順ではウィンドウのすぐ手前
に配置されます。したがって対象を覆う別のウィンドウは目印も覆います。すべてのデスク
トップに保持されたウィンドウは、目印も一緒に連れて移動します。

独自の枠を描くウィンドウ（ブラウザーや UWP アプリなど）はタイトルバーの座標を常に
公開するとは限りません。その場合、目印は表示枠の右上隅に配置されます。

## 設定

メニューの**設定…**から開きます。ロゴ、名称、**バージョン番号**に続いて次の項目が
並びます。

| 設定 | 内容 |
|---|---|
| **Windows と一緒に起動** | `HKCU\...\CurrentVersion\Run` に書き込みます。状態の拠り所はレジストリだけです。チェックボックスは実際の状態を読み直し、書き込みに失敗した場合は表示を合わせ直します |
| **終了時にすべて解除** | ウィンドウが固定されたまま残るのを防ぎます |
| **通知を表示** | 情報通知のみを隠します。**エラーは常に通知されます**。黙らせると、失敗した操作が「何も起きなかった」ように見えてしまうためです |
| **言語** | メニュー、ツールチップ、通知を含めて即座に反映されます |
| **GitHub リポジトリ** | 更新確認に使う取得元。`所有者/リポジトリ` の形式で指定します |

設定は `%APPDATA%\Freeze Ray\settings.ini` に保存されます。`キー=値` 形式の素朴な
ファイルで、手で読んで直せます。初回起動時の言語は Windows に従います（システムが
フランス語でなければ英語）。

文言はリソースファイルではなく [Strings.cs](../Strings.cs) に言語ごとの表として
置いてあります。Windows 付属のコンパイラーだけでビルドできる状態を保つためです。
言語の追加は、表を 1 つとドロップダウンの項目を 1 つ足すだけです。

### 更新

**更新を確認**すると、指定したリポジトリについて GitHub の公開リリース API に問い
合わせ、バージョン番号を比較し、ダウンロードページを開くか尋ねます。

**このアプリはあえて自動更新しません。** 実行中の実行ファイルを置き換えるには補助
プロセスが必要で、署名も整合性検証もないまま行えば攻撃経路になります。この規模の
ユーティリティに見合う取引ではありません。

## ソースからビルドする

SDK は不要です。Windows に既にある .NET Framework 4 付属の C# コンパイラーだけで
足ります。

```bat
build.bat
```

ソースの隣に `Freeze Ray.exe` が生成されます。ロゴは**実行ファイルに埋め込まれて
いる**ため、バイナリ単体で動作します。

## ロゴを差し替える

| ファイル | 役割 |
|---|---|
| `assets/icon.png` | 元のロゴ（512×512、透過）— 通知領域アイコン、選択カーソル、タイトルバーの目印 |
| `assets/app.ico` | `tools/MakeIcon.cs` が**生成** — ファイルおよびウィンドウのアイコン |
| `assets/Freeze Ray.png` | 設定画面のヘッダー専用の挿絵 |

`icon.ico` には元々 256×256 の画像が 1 つしか入っておらず、通知領域（16×16）や
タイトルバー向けに Windows 側が縮小することになり、ぼやけた仕上がりになっていま
した。そこで `tools/MakeIcon.cs` が PNG から必要な 9 サイズ（16 → 256）を高品質な
再サンプリングで事前生成します。

ロゴを変えるには `assets/icon.png` を置き換えて再生成します。

```bat
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /out:MakeIcon.exe /r:System.Drawing.dll tools\MakeIcon.cs
MakeIcon.exe
build.bat
```

## 仕組み

### 仮想デスクトップ

すべてのデスクトップにウィンドウを保持する処理は、タスクビューの右クリックにある
*「このウィンドウをすべてのデスクトップに表示する」*とまったく同じ仕組みを使って
います。非公開のシェル COM インターフェイス `IApplicationViewCollection` と
`IVirtualDesktopPinnedApps` が提供するものです。
[VirtualDesktop.cs](../VirtualDesktop.cs) を参照してください。

### マウスキャプチャではなくオーバーレイによる選択

選択は `SetCapture` ではなく、**すべてのモニターを覆う透明なレイヤー**で実現して
います。マウスキャプチャがメッセージを転送するのは、ボタンが押されている間か、
ポインターがキャプチャ側ウィンドウの上にある間だけです。Spy++ の検索ツールを
*ドラッグ*して使うのはそのためです。ボタンを押していない状態では、通過した各
ウィンドウが自分のカーソルを設定し続けるため、ロゴは決して現れませんでした。
オーバーレイならポインターは常に自前のウィンドウの上にあり、カーソルを設定でき、
クリックも受け取れます。[WindowPicker.cs](../WindowPicker.cs) を参照。

### 目印

目印はピクセル単位の透過ウィンドウ（`WS_EX_LAYERED` + `UpdateLayeredWindow`）で、
どんな背景の上でもロゴのアンチエイリアスを保ちます。フォーカスを一切奪わないため、
クリックしても対象ウィンドウは非アクティブになりません。透明な部分のクリックは下の
タイトルバーへ通り抜けます。

**目印の位置を動かす**設定は [WindowMarker.cs](../WindowMarker.cs) の
`BUTTON_GAP` ひとつだけです（最初のシステムボタンとの間隔、4 px）。小さくするほど
右に寄り、0 未満では最小化ボタンに重なります。

ボタン列の幅は直接取得できません。システムメトリック `SM_CXSIZE` は 36 px を返し
ますが、Windows 10 が実際に描くボタンは 46 px です（ピクセル単位で計測：グリフは
46 px 間隔で中央揃え）。一方で表示倍率には正しく追従するため、コードでは 46/36 の
比率を用いています。

### 「最前面」を拒否するアプリ

一部のアプリは重なり順の変更を**拒否します**。`WM_WINDOWPOSCHANGING` を横取りし、
その場で変更を無効化するのです。すると `SetWindowPos` は**何もしないまま成功を
返します**。動画再生中の VLC がこの挙動を示しました（計測：呼び出しの 1 秒後も
フラグは付いていませんでした）。

そのためコードには 2 つの備えがあります。

- `SWP_NOSENDCHANGING` フラグでその通知を抑止し、アプリから拒否権を奪います。
- 戻り値を信用せず、**あとから状態を読み直します**。本当の失敗を黙って呑み込まず、
  きちんと通知するためです。

### 通知

情報通知には、システムの青い「i」ではなく**アプリのロゴ**を表示します。WinForms
では実現できません。`NotifyIcon.ShowBalloonTip` はシステムアイコンしか受け付けず、
列挙値の範囲外を渡すと拒否されるからです。そこでシェルを直接呼び
（`Shell_NotifyIcon` に `NIIF_USER`）、WinForms が作成した項目の内部識別を再利用し
ています。[Notifications.cs](../Notifications.cs) を参照。その内部仕様が変わった
場合は、標準の通知に自動的に戻ります。

通知のヘッダーには `Freeze Ray.exe` と表示されます。Windows が実行ファイル名を
入れるためです。`AppUserModelID` を宣言しても変わりません（検証済み）。拡張子なしの
名前にするには、スタートメニューにショートカットを登録するしかありません。

## 既知の制限

- **昇格した**プロセスが所有するウィンドウは、Freeze Ray も管理者として実行して
  いる場合にのみ変更できます。
- 仮想デスクトップに使う COM インターフェイスは非公開で、識別子は Windows の
  バージョンごとに変わります。ここで使っている GUID は
  **Windows 10 1803 → 22H2** のもので、ビルド **19045** で検証しました。
  Windows 11 では `IVirtualDesktopPinnedApps` の IID が異なり、
  [VirtualDesktop.cs](../VirtualDesktop.cs) の調整が必要です。
- 固定はアプリではなくウィンドウに対して働きます。閉じたウィンドウを開き直した
  場合は、もう一度固定し直してください。
