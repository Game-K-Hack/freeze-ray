## Что это даёт

Windows позволяет переключать виртуальные рабочие столы сочетанием
`Ctrl + Win + ←/→`, но всё, на что вы смотрели, исчезает вместе с покинутым
столом. Freeze Ray закрепляет окно так, что оно **остаётся видимым, ровно на том
же месте, на каждом рабочем столе**.

Это утилита области уведомлений в духе **DeskPin**, с двумя независимыми
действиями:

- **Удерживать на экране** — окно следует за вами по всем виртуальным столам.
- **Поверх остальных** — окно остаётся выше других, классическое поведение
  DeskPin.

Оба действия можно применить к одному и тому же окну.

## Требования

- **Windows 10** (собрано и проверено на сборке 19045, 22H2).
- **.NET Framework 4** — уже входит в состав Windows, ставить ничего не нужно.

> В Windows 11 недокументированные интерфейсы оболочки для виртуальных рабочих
> столов имеют другие идентификаторы. См. [Известные ограничения](#известные-ограничения).

## С чего начать

1. Скачайте `Freeze Ray.exe` из
   [последнего выпуска](https://github.com/Game-K-Hack/freeze-ray/releases/latest)
   или [соберите сами](#сборка-из-исходников).
2. Запустите. Никакого окна не появится — только значок в области уведомлений.
3. Щёлкните по значку → **Удерживать на экране (все рабочие столы)…**
4. Курсор превратится в логотип приложения: щёлкните по нужному окну. На его
   заголовке появится маленький логотип.
5. Переключите рабочий стол сочетанием `Ctrl + Win + ←/→`: окно на месте.
6. Чтобы освободить окно, щёлкните по логотипу на его заголовке.

Исполняемый файл самодостаточен: ни установщик, ни папка `assets` не нужны.

## Как пользоваться

**Ни одна глобальная комбинация клавиш не регистрируется**, поэтому конфликт с
другими программами исключён. Всё идёт через значок, и **щелчок — левый или
правый — открывает меню**:

| Пункт | Действие |
|---|---|
| **Удерживать на экране (все рабочие столы)…** | Включает режим выбора; окно, по которому вы щёлкнете, будет следовать за всеми столами |
| **Поверх остальных…** | Включает режим выбора; выбранное окно получает `TOPMOST` |
| **Закреплённые окна (n)** | Перечисляет их с состоянием; щелчок по любому освобождает его |
| **Освободить всё** | Возвращает все окна в обычное состояние |
| **Параметры…** | Открывает окно настроек |
| **Выход** | |

### Режим выбора

После щелчка по одному из первых двух пунктов **курсор превращается в логотип**,
показывая, что ожидается окно; следующий щелчок его выбирает. Этот щелчок
поглощается Freeze Ray, поэтому он не нажимает то, что находится под указателем.

- **Esc** или **правый щелчок** отменяют. Щелчок по рабочему столу или панели
  задач тоже отменяет, без сообщений.
- Выбор уже закреплённого окна освобождает его — действие переключающее.
- Всплывающая подсказка значка всегда показывает текущее состояние.

### Метка на заголовке окна

Закреплённое окно получает **логотип на своём заголовке**, слева от системных
кнопок. **Щелчок по нему освобождает окно** и убирает метку.

Метка следует за окном при перемещении и изменении размера, исчезает при
сворачивании и располагается непосредственно перед окном по глубине — поэтому
другое окно, перекрывающее цель, перекрывает и метку. Окно, удерживаемое на всех
рабочих столах, забирает метку с собой.

Окна с собственной рамкой (браузеры, приложения UWP…) не всегда публикуют
геометрию своего заголовка; тогда метка помещается в правый верхний угол видимой
рамки.

## Параметры

Открываются пунктом **Параметры…** в меню. В окне показаны логотип, название и
**номер версии**, а затем:

| Параметр | Пояснение |
|---|---|
| **Запускать вместе с Windows** | Пишет в `HKCU\...\CurrentVersion\Run`. Единственный источник истины — реестр: флажок перечитывает действительное состояние и возвращается к нему, если запись не удалась |
| **Освобождать всё при выходе** | Не оставляет закреплённых окон |
| **Показывать уведомления** | Скрывает только информационные всплывающие сообщения — **об ошибках сообщается всегда**, иначе неудавшееся действие выглядело бы как действие без последствий |
| **Язык** | Применяется сразу, включая меню, подсказку и уведомления |
| **Проверять обновления при запуске** | Обращается к GitHub при старте; молчит, если новой версии нет |

Настройки хранятся в `%APPDATA%\Freeze Ray\settings.ini` — простом файле вида
`ключ=значение`, который можно прочитать и поправить вручную. При первом запуске язык следует за языком Windows, иначе используется английский. Доступны девять языков: английский, французский, немецкий, испанский, итальянский, японский, корейский, русский и китайский.

Тексты лежат в [Strings.cs](../Strings.cs) — по таблице на язык вместо файлов
ресурсов, чтобы проект по-прежнему собирался компилятором, входящим в состав
Windows. Добавить язык — значит добавить таблицу и одну строку в выпадающий
список.

### Обновления

**Проверить обновления** обращается к публичному API выпусков GitHub для
указанного репозитория, сравнивает номера версий и предлагает открыть страницу
загрузки.

**Приложение намеренно не обновляет себя само.** Замена работающего
исполняемого файла требует вспомогательного процесса, а делать это без подписи и
проверки целостности — открыть путь для атаки: для утилиты такого размера обмен
невыгодный.

## Сборка из исходников

Никакой SDK не нужен: достаточно компилятора C# из .NET Framework 4, уже
имеющегося в Windows.

```bat
build.bat
```

Рядом с исходниками появится `Freeze Ray.exe`. Логотип **встроен в исполняемый
файл**, поэтому двоичный файл работает сам по себе.

## Замена логотипа

| Файл | Назначение |
|---|---|
| `assets/icon.png` | Исходный логотип (512×512, прозрачный) — значок области уведомлений, курсор выбора и метка на заголовке |
| `assets/app.ico` | **Создаётся** `tools/MakeIcon.cs` — значок файла и окна |
| `assets/Freeze Ray.png` | Иллюстрация только для шапки окна параметров |

Изначально `icon.ico` содержал единственное изображение 256×256, которое Windows
пришлось бы уменьшать самостоятельно для области уведомлений (16×16) и заголовка
окна, с размытым результатом. Поэтому `tools/MakeIcon.cs` заранее вычисляет девять
нужных размеров (16 → 256) из PNG с качественной передискретизацией.

Чтобы сменить логотип, замените `assets/icon.png` и пересоздайте:

```bat
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /out:MakeIcon.exe /r:System.Drawing.dll tools\MakeIcon.cs
MakeIcon.exe
build.bat
```

## Как это устроено

### Виртуальные рабочие столы

Удержание окна на всех столах использует тот же механизм, что и пункт контекстного
меню *«Показать это окно на всех рабочих столах»* в представлении задач; его дают
недокументированные COM-интерфейсы оболочки `IApplicationViewCollection` и
`IVirtualDesktopPinnedApps` — см. [VirtualDesktop.cs](../VirtualDesktop.cs).

### Выбор через наложение, а не через захват мыши

Выбор опирается на **прозрачный слой, покрывающий все мониторы**, а не на
`SetCapture`. Захват мыши перенаправляет сообщения только пока удерживается
кнопка или пока указатель находится над захватившим окном — именно поэтому
инструмент поиска в Spy++ используют *перетаскиванием*. Без нажатой кнопки каждое
окно под указателем продолжало устанавливать собственный курсор, и логотип не
появлялся никогда. Со слоем указатель постоянно находится над нашим собственным
окном: оно задаёт курсор и получает щелчок. См.
[WindowPicker.cs](../WindowPicker.cs).

### Метка

Метка — это окно с попиксельной прозрачностью (`WS_EX_LAYERED` +
`UpdateLayeredWindow`), что сохраняет сглаживание логотипа на любом фоне. Она
никогда не получает фокус, поэтому щелчок по ней не деактивирует целевое окно, а
прозрачные области пропускают щелчок к заголовку под ней.

**Чтобы сдвинуть метку**, есть одна настройка в
[WindowMarker.cs](../WindowMarker.cs): `BUTTON_GAP` — отступ до первой системной
кнопки (4 px). Чем он меньше, тем правее метка; ниже нуля она наезжает на кнопку
«Свернуть».

Ширину блока кнопок нельзя прочитать напрямую: системная метрика `SM_CXSIZE`
сообщает 36 px там, где Windows 10 рисует кнопки шириной 46 px (измерено по
пикселям: глифы отцентрованы через каждые 46 px). Зато она правильно следует
масштабированию экрана — отсюда соотношение 46/36 в коде.

### Приложения, накладывающие вето на «поверх остальных»

Некоторые приложения **отказываются** менять свой порядок по глубине: они
перехватывают `WM_WINDOWPOSCHANGING` и по пути нейтрализуют изменение. Тогда
`SetWindowPos` возвращает **успех, ничего не сделав** — так ведёт себя VLC во
время воспроизведения видео (измерено: флага не было и через целую секунду после
вызова).

Отсюда две предосторожности в коде:

- флаг `SWP_NOSENDCHANGING` подавляет это уведомление и лишает приложение права
  вето;
- состояние **перечитывается после вызова** вместо доверия возвращённому
  значению, чтобы настоящая неудача была показана, а не проглочена молча.

### Уведомления

Информационные сообщения показывают **логотип приложения** вместо синей системной
«i». WinForms так не умеет: `NotifyIcon.ShowBalloonTip` принимает только системные
значки и отвергает любое значение вне своего перечисления. Поэтому обращение идёт
напрямую к оболочке (`Shell_NotifyIcon` с `NIIF_USER`), с повторным использованием
внутреннего идентификатора записи, созданной WinForms — см.
[Notifications.cs](../Notifications.cs). Если эта внутренняя деталь когда-нибудь
изменится, код вернётся к стандартному уведомлению.

В заголовке уведомления отображается `Freeze Ray.exe`: Windows подставляет туда
имя исполняемого файла. Объявление `AppUserModelID` ничего не меняет (проверено);
имя без расширения дало бы только создание ярлыка в меню «Пуск».

## Известные ограничения

- Окно, принадлежащее процессу **с повышенными правами**, можно изменить, только
  если Freeze Ray тоже запущен от имени администратора.
- COM-интерфейсы для виртуальных рабочих столов не документированы, и их
  идентификаторы меняются от версии к версии Windows. Здесь используются GUID
  для **Windows 10 1803 → 22H2**, проверенные на сборке **19045**. В Windows 11 у
  `IVirtualDesktopPinnedApps` другой IID, и
  [VirtualDesktop.cs](../VirtualDesktop.cs) придётся поправить.
- Закрепление относится к окну, а не к приложению: если окно закрыть и открыть
  заново, его нужно закрепить снова.
