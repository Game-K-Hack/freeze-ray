## 무엇을 하는 도구인가

Windows에서는 `Ctrl + Win + ←/→`로 가상 데스크톱을 전환할 수 있지만, 보고 있던
것은 떠나온 데스크톱과 함께 사라집니다. Freeze Ray는 창을 고정해 **모든 데스크톱
에서 정확히 같은 자리에 계속 보이도록** 합니다.

**DeskPin**의 정신을 잇는 알림 영역 유틸리티이며, 서로 독립된 두 가지 동작을
제공합니다.

- **화면에 유지** — 모든 가상 데스크톱을 따라다닙니다.
- **항상 위에** — 다른 창들보다 앞에 머무릅니다. DeskPin의 고전적인 동작입니다.

같은 창에 둘 다 적용할 수 있습니다.

## 요구 사항

- **Windows 10** (빌드 19045, 22H2에서 빌드 및 검증).
- **.NET Framework 4** — Windows에 이미 포함되어 있어 따로 설치할 것이 없습니다.

> Windows 11에서는 가상 데스크톱에 쓰이는 비공개 셸 인터페이스의 식별자가
> 다릅니다. [알려진 제한](#알려진-제한)을 참고하세요.

## 시작하기

1. [최신 릴리스](https://github.com/Game-K-Hack/freeze-ray/releases/latest)에서
   `Freeze Ray.exe`를 내려받거나 [직접 빌드](#소스에서-빌드하기)하세요.
2. 실행합니다. 창은 열리지 않고 알림 영역에 아이콘만 나타납니다.
3. 아이콘을 클릭 → **화면에 유지(모든 데스크톱)…**
4. 커서가 앱 로고로 바뀝니다. 유지하려는 창을 클릭하세요. 제목 표시줄에 작은 로고가
   붙습니다.
5. `Ctrl + Win + ←/→`로 데스크톱을 전환해도 창은 그대로 있습니다.
6. 해제하려면 제목 표시줄의 로고를 클릭합니다.

설치 방법은 두 가지입니다. `Freeze Ray Setup.exe`를 실행하면 라이선스를 보여 주고,
설치 폴더를 고르게 하며, 바탕 화면과 시작 메뉴 바로 가기를 만들어 줍니다. 또는
`Freeze Ray.exe`를 원하는 곳에 두기만 해도 됩니다 — 단독으로 동작하며 `assets`
폴더가 필요 없습니다.

## 사용법

**전역 단축키를 전혀 등록하지 않으므로** 다른 프로그램과 충돌할 일이 없습니다.
모든 조작은 아이콘을 통하며, **왼쪽이든 오른쪽이든 클릭하면 메뉴가 열립니다.**

| 항목 | 동작 |
|---|---|
| **화면에 유지(모든 데스크톱)…** | 지정 모드로 들어가며, 클릭한 창이 모든 데스크톱을 따라다닙니다 |
| **항상 위에…** | 지정 모드로 들어가며, 클릭한 창이 `TOPMOST`가 됩니다 |
| **고정된 창 (n)** | 상태와 함께 나열하며, 클릭하면 해제됩니다 |
| **모두 해제** | 모든 창을 원래대로 되돌립니다 |
| **설정…** | 설정 창을 엽니다 |
| **종료** | |

### 지정 모드

위의 두 항목 중 하나를 클릭하면 **커서가 앱 로고로 바뀌어** 창을 기다리고 있음을
알립니다. 다음 클릭으로 대상이 정해집니다. 그 클릭은 Freeze Ray가 소비하므로,
포인터 아래에 있는 것은 눌리지 않습니다.

- **Esc** 또는 **오른쪽 클릭**으로 취소합니다. 바탕 화면이나 작업 표시줄을 클릭해도
  메시지 없이 취소됩니다.
- 이미 고정된 창을 지정하면 해제됩니다. 동작은 토글입니다.
- 아이콘 툴팁에 현재 상태가 항상 표시됩니다.

### 제목 표시줄의 표식

고정된 창에는 시스템 단추 바로 왼쪽에 **로고가 표시됩니다**. **그 로고를 클릭하면
창이 해제되고** 표식도 사라집니다.

표식은 창을 옮기거나 크기를 바꿔도 따라오고, 최소화하면 사라지며, 겹침 순서에서
창의 바로 앞에 놓입니다. 따라서 대상을 덮는 다른 창은 표식도 함께 덮습니다. 모든
데스크톱에 유지되는 창은 표식도 함께 데리고 다닙니다.

사용자 지정 프레임을 쓰는 창(브라우저, UWP 앱 등)은 제목 표시줄의 좌표를 늘
공개하지는 않습니다. 그럴 때 표식은 보이는 프레임의 오른쪽 위 모서리에 놓입니다.

## 설정

메뉴의 **설정…**으로 엽니다. 로고와 이름, **버전 번호**에 이어 다음 항목이 있습니다.

| 설정 | 설명 |
|---|---|
| **Windows 시작 시 실행** | `HKCU\...\CurrentVersion\Run`에 기록합니다. 상태의 근거는 레지스트리뿐입니다. 확인란은 실제 상태를 다시 읽고, 기록에 실패하면 표시를 되돌립니다 |
| **종료할 때 모두 해제** | 창이 고정된 채 남는 것을 막습니다 |
| **알림 표시** | 정보 알림만 숨깁니다. **오류는 항상 알립니다.** 오류를 감추면 실패한 동작이 아무 일도 없었던 것처럼 보이기 때문입니다 |
| **언어** | 메뉴, 툴팁, 알림까지 즉시 반영됩니다 |
| **시작할 때 업데이트 확인** | 시작 시 GitHub에 조회합니다. 새 버전이 없으면 아무것도 표시하지 않습니다 |

설정은 `settings.ini`에 저장됩니다. `키=값` 형식의 단순한
파일이라 손으로 읽고 고칠 수 있습니다. 첫 실행 시 언어는 Windows를 따르며, 없으면 영어로 대체됩니다. 영어, 프랑스어, 독일어, 스페인어, 이탈리아어, 일본어, 한국어, 러시아어, 중국어의 9개 언어를 제공합니다.

이 파일은 **애플리케이션과 같은 위치**에 있습니다. 설치 전체가 폴더 하나에 담기므로
USB 메모리에 복사하거나 한 번에 지울 수 있습니다. `Program Files`에 둔 경우처럼 그
폴더에 쓸 수 없으면, 설정은 사라지지 않고 `%APPDATA%\Freeze Ray`로 물러납니다.

문구는 리소스 파일이 아니라 [Strings.cs](../Strings.cs)에 언어별 표로 들어 있습니다.
Windows에 딸린 컴파일러만으로 빌드할 수 있는 상태를 유지하기 위해서입니다. 언어를
추가하려면 표 하나와 드롭다운 항목 하나만 더하면 됩니다.

### 업데이트

**업데이트 확인**은 설정한 저장소에 대해 GitHub의 공개 릴리스 API를 조회하고,
버전 번호를 비교한 뒤 다운로드 페이지를 열지 묻습니다.

**이 앱은 의도적으로 스스로 업데이트하지 않습니다.** 실행 중인 실행 파일을 교체
하려면 보조 프로세스가 필요하고, 서명이나 무결성 검증 없이 그렇게 하면 공격
경로가 됩니다. 이 정도 규모의 유틸리티에 걸맞은 거래가 아닙니다.

## 소스에서 빌드하기

SDK는 필요 없습니다. Windows에 이미 있는 .NET Framework 4의 C# 컴파일러면
충분합니다.

```bat
build.bat
```

소스 옆에 `Freeze Ray.exe`가 만들어집니다. 로고는 **실행 파일에 포함되어 있어**
바이너리 하나로 동작합니다.

## 로고 교체하기

| 파일 | 역할 |
|---|---|
| `assets/icon.png` | 원본 로고(512×512, 투명) — 알림 영역 아이콘, 지정 커서, 제목 표시줄 표식 |
| `assets/app.ico` | 여러 크기의 아이콘(16 → 256) — 파일 및 창 아이콘 |
| `assets/Freeze Ray.png` | 설정 화면 머리말에만 쓰이는 삽화 |

로고를 바꾸려면 `assets/icon.png`를 교체하고, 아홉 가지 표준 크기(16, 20, 24, 32, 40,
48, 64, 128, 256)를 담은 `assets/app.ico`를 원하는 아이콘 편집기로 만든 뒤 `build.bat`을
실행하세요.

256×256 이미지 하나로는 부족합니다. 알림 영역(16×16)과 제목 표시줄용으로 Windows가
직접 줄여야 해서 결과가 흐릿해집니다.

## 동작 원리

### 가상 데스크톱

창을 모든 데스크톱에 유지하는 기능은 작업 보기의 마우스 오른쪽 메뉴
*'이 창을 모든 데스크톱에 표시'*와 똑같은 구조를 사용합니다. 비공개 셸 COM
인터페이스 `IApplicationViewCollection`과 `IVirtualDesktopPinnedApps`가 제공하며,
[VirtualDesktop.cs](../VirtualDesktop.cs)를 참고하세요.

### 마우스 캡처가 아닌 오버레이로 지정하기

지정 기능은 `SetCapture`가 아니라 **모든 모니터를 덮는 투명한 계층**에 기대고
있습니다. 마우스 캡처는 버튼이 눌려 있는 동안이나 포인터가 캡처한 창 위에 있을
때만 메시지를 돌려줍니다. Spy++의 찾기 도구를 *끌어서* 쓰는 이유가 그것입니다.
버튼을 누르지 않으면 지나치는 창마다 자기 커서를 계속 지정해서 로고가 결코 나타
나지 않았습니다. 오버레이를 쓰면 포인터가 늘 우리 창 위에 있으므로, 커서를
지정하고 클릭도 받습니다. [WindowPicker.cs](../WindowPicker.cs)를 참고하세요.

### 표식

표식은 픽셀 단위 투명 창(`WS_EX_LAYERED` + `UpdateLayeredWindow`)이라 어떤 배경
위에서도 로고의 앤티앨리어싱이 살아 있습니다. 포커스를 전혀 가져가지 않으므로
클릭해도 대상 창이 비활성화되지 않고, 투명한 부분의 클릭은 아래 제목 표시줄로
통과합니다.

**표식을 옮기는** 설정은 [WindowMarker.cs](../WindowMarker.cs)의 `BUTTON_GAP`
하나뿐입니다(첫 시스템 단추와의 간격, 4 px). 작을수록 오른쪽으로 붙고, 0보다
작으면 최소화 단추와 겹칩니다.

단추 묶음의 너비는 직접 읽을 수 없습니다. 시스템 메트릭 `SM_CXSIZE`는 36 px를
보고하지만 Windows 10이 실제로 그리는 단추는 46 px입니다(픽셀 단위로 측정: 글리프가
46 px 간격으로 중앙 정렬). 다만 화면 배율은 정확히 따라가므로 코드에서는 46/36
비율을 씁니다.

### '항상 위에'를 거부하는 앱

일부 앱은 겹침 순서 변경을 **거부합니다.** `WM_WINDOWPOSCHANGING`을 가로채 지나
가는 길에 변경을 무력화합니다. 그러면 `SetWindowPos`는 **아무것도 하지 않고 성공을
반환합니다.** 동영상을 재생 중인 VLC가 이렇게 동작했습니다(측정: 호출 1초 뒤에도
플래그가 없었습니다).

그래서 코드에 두 가지 대비를 두었습니다.

- `SWP_NOSENDCHANGING` 플래그로 그 알림을 억제해 앱에서 거부권을 빼앗습니다.
- 반환값을 믿는 대신 **나중에 상태를 다시 읽습니다.** 진짜 실패를 삼키지 않고
  알리기 위해서입니다.

### 알림

정보 알림에는 시스템의 파란 'i' 대신 **앱 로고**를 표시합니다. WinForms로는 할 수
없습니다. `NotifyIcon.ShowBalloonTip`은 시스템 아이콘만 받고 열거형 범위를 벗어난
값은 거부하기 때문입니다. 그래서 셸을 직접 호출하고(`Shell_NotifyIcon`에
`NIIF_USER`), WinForms가 만든 항목의 내부 식별자를 재사용합니다.
[Notifications.cs](../Notifications.cs)를 참고하세요. 그 내부 구현이 바뀌면 코드는
표준 알림으로 되돌아갑니다.

알림 머리말에는 `Freeze Ray.exe`가 표시됩니다. Windows가 실행 파일 이름을 넣기
때문입니다. `AppUserModelID`를 선언해도 달라지지 않습니다(확인함). 확장자 없는
이름을 쓰려면 시작 메뉴에 바로 가기를 설치하는 수밖에 없습니다.

## 알려진 제한

- **권한이 상승된** 프로세스가 소유한 창은 Freeze Ray도 관리자로 실행해야 바꿀 수
  있습니다.
- 가상 데스크톱에 쓰는 COM 인터페이스는 문서화되어 있지 않고 식별자가 Windows
  버전마다 달라집니다. 여기서 쓰는 GUID는 **Windows 10 1803 → 22H2**의 것이며
  빌드 **19045**에서 검증했습니다. Windows 11에서는
  `IVirtualDesktopPinnedApps`의 IID가 달라 [VirtualDesktop.cs](../VirtualDesktop.cs)를
  손봐야 합니다.
- 고정은 앱이 아니라 창에 적용됩니다. 닫았던 창을 다시 열면 다시 고정해야 합니다.

## 라이선스

집에서든 직장에서든 기간 제한 없이 자유롭게 사용할 수 있습니다. 복사, 연구, 수정,
배포도 가능하지만 **판매하지 않을 것**, 공개하는 수정판에는 **작성자를 밝힐 것**,
그리고 모든 복사본에 라이선스를 함께 둘 것이 조건입니다.
